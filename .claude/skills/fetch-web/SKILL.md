# fetch-web

## 입력
- 기업명 1개

## 왜 필요한가
`judgment-rules.md`의 여러 대체지표(Underpriced Customer Love의 리뷰·검색 트렌드, 스크리닝 체크리스트의 ESG·신규 경쟁 브랜드 동향, 시장성의 시가총액)는 DART/FnGuide/FRED 데이터 키트 밖의 정보다. 이 스킬은 다른 fetch-* 스킬과 달리 API 키/`lib/` 클라이언트를 쓰지 않고, Claude Code의 `WebSearch`/`WebFetch` 툴을 직접 사용해 수집한다.

## 동작
1. `WebSearch`로 아래 쿼리들을 실행한다 (기업명은 실제 대상으로 치환):
   - `"<기업명>" 리뷰 후기` — Expressed Love(리뷰) 및 가격탄력성 관련 신호
   - `"<기업명>" 신제품 OR 가격 인상` — WTP(가격결정력) Catalyst 확인
   - `"<기업명>" 경쟁사 OR 신규 브랜드` — 경쟁력/Moat 침식 신호
   - `"<기업명>" ESG OR 소송 OR 제재` — 스크리닝 체크리스트 ESG 항목
   - `"<기업명>" 시가총액` (또는 `"<티커>" market cap`) — **시장성 항목·Valuation Multiple 계산용**. 이 레포 데이터 키트(DART/FRED/FnGuide)에는 시세 소스가 없어(README "공통 데이터 공백" 참고) KRX 공식 API 대신 웹 검색으로 채운다.
2. 검색 결과 중 관련성 높은 기사 상위 몇 건은 `WebFetch`로 본문을 확인해 핵심 내용을 요약한다. **아래 "출처 신뢰도 필터"의 차단 목록에 해당하는 도메인은 검색 결과 상위에 나오더라도 건너뛴다** — 나무위키가 한국 기업 검색에서 1순위로 뜨는 경우가 흔한데, 이것부터 `WebFetch`하지 않는다. 시가총액은 네이버금융·Google Finance·공식 IR 자료 등 신뢰도 높은 소스를 우선하고, 조회 시점을 반드시 함께 기록한다(시세는 변동성이 커서 "며칠 전 값"이라는 사실 자체가 중요한 정보다).
3. 기업 공식 홈페이지가 확인되면 IR/뉴스룸 페이지를 `WebFetch`로 확인한다(가격 정책, 신규 채널·매장 발표 등).
4. 결과를 `data/cache/<기업명>/web.json`에 저장한다. 각 항목에는 반드시 출처 URL, 제목, 수집일자, 1~2문장 요약을 포함한다. 시가총액은 별도 `market_data` 필드로 저장한다:
   ```json
   "market_data": {
     "market_cap": "값 + 단위",
     "price": "값(있으면)",
     "as_of": "조회 시점 기준일",
     "source_url": "...",
     "confidence": "Medium(3rd-party 웹, 공식 API 아님)"
   }
   ```

## 출력
- `data/cache/<기업명>/web.json` — `judge-underpriced-customer-love`, `screen-fundamentals` 스킬이 참조할 Proxy 원자료(뉴스/리뷰/ESG 등 + `market_data`).

## 원칙
- 이 스킬로 얻는 데이터는 전부 **Proxy(Low~Medium Confidence)**로 취급한다 — `.claude/skills/judge-underpriced-customer-love/references/underpriced-customer-love-framework.md` K절의 데이터 신뢰도 처리 원칙(Medium 0.8x, Low 0.6x 할인)을 그대로 적용한다. `market_data`도 예외 없이 Medium으로 표시하고, 공식 API처럼 취급하지 않는다.
- 검색 결과가 없거나 확인이 안 되는 항목(시가총액 포함)은 "데이터 없음"으로 명시한다. 추측이나 일반 상식으로 채우지 않는다. **차단 목록에 걸려 못 쓰는 소스뿐이어도 마찬가지다 — 위키/블로그로 억지로 빈칸을 채우지 않는다.**

## 출처 신뢰도 필터 (2026-08-13 추가)

실제 실행(백화점 산업 비교, 5개사)에서 나무위키·브런치 같은 저신뢰 출처가 다수 인용되는 문제가 발견돼 추가했다. `WebSearch` 결과는 관련성 순이지 신뢰도 순이 아니므로, 상위에 뜨더라도 아래 기준으로 직접 걸러야 한다.

### 차단 목록 — 수집 자체를 하지 않는다 (WebFetch 대상에서 제외)
- **크라우드 편집 위키**: 나무위키, 위키백과 등 — 누구나 편집 가능해 편집 시점의 서술을 사실로 보증할 수 없다.
- **개인 블로그 플랫폼**: 브런치, 티스토리, 네이버 블로그, 벨로그 등 — 저자 개인의 주관적 글로, 매체로서의 편집·팩트체크 책임 주체가 없다.
- **익명 커뮤니티 게시판**: 디시인사이드, 에펨코리아, 클리앙, 오늘의유머, 뽐뿌 등.
- **광고성/네이티브 광고 콘텐츠**: 기업이 대가를 지불한 것으로 보이는 홍보성 게시물(협찬 표기, 기자 없는 보도자료 재게재 등).

이런 도메인이 검색 결과에 나오면 그 링크는 `WebFetch`하지 않고 건너뛰어 다음 결과로 넘어간다. 대체할 상위 등급 소스가 없으면 그 항목은 "데이터 없음"으로 명시한다(아래 예외 항목은 별도).

### 우선 사용 — 언론사·공식 채널
전국지·경제지·통신사(연합뉴스, 한국경제, 매일경제, 조선비즈 등 바이라인 있는 기사), 업계 전문지(패션비즈 등), 회사 공식 IR/뉴스룸/공시, 증권사 리포트·애널리스트 노트, 정부·공공기관 발표(공정위·금감원 등), 신뢰도 높은 증권 정보 사이트(네이버금융, Google Finance, 한경 마켓 등)를 우선 검색·인용한다.

### 예외적으로 허용 — 단, Low Confidence + 참고용으로만, 판단 근거의 핵심으로 쓰지 않음
- **정량적 집계가 있는 리뷰/평판 플랫폼**: Tripadvisor(이용 후기 총평), 잡플래닛·Teamblind(재직자 리뷰) 등은 완전히 배제하지 않되, ULRS의 "소비자 애착(Love)" 신호로 직접 쓰지 않는다 — 특히 잡플래닛·Teamblind는 **직원** 리뷰지 **소비자** 리뷰가 아니므로 Customer Love 지표로 착각해 쓰지 않는다(참고 정황으로만 표기).
- 이 예외에 해당해도 반드시 `Low Confidence`로 표시하고, 어떤 Gate(예: Data Integrity Gate, Consensus Gate)의 통과·발동 여부를 이 소스 하나로 단독 결정하지 않는다 — 상위 등급 소스와 함께 나올 때만 보조 근거로 쓴다.

### web.json 저장 규칙
각 항목에 소스 등급을 함께 남긴다: `"tier": "primary" | "medium" | "low_exception"`. 차단 목록에 걸려 제외한 검색 결과가 있었다면(대체 소스를 못 찾은 경우) `"skipped_low_quality": ["도메인 또는 URL", ...]`로 어떤 저신뢰 소스를 걸러냈는지 남긴다 — 나중에 판단 스킬이나 사용자가 "왜 이 항목이 데이터 없음인지" 추적할 수 있도록.
